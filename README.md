# 万物的来路 · 发现型科技树

一个可以从原始能力一路探索到计算、智能和自主研究的私人知识地图。不是让一个“全知者”照着技术名录点亮技能，而是把**怎样观察、尝试、解释、验证，并获得新能力**放回科技树。

原来的易拉罐知识星图仍然保留，成为矿业—化工—电力—铝冶炼—薄壁制造这条工业支线。

当前主干有 **112 个节点、410 条关联、9 个阶段、5 条连续探索路线**。其中 343 条为使能关系，67 条为理论解释，参考来源共 69 项。

## 从左向右：新的东西在右边

地图分为九个可探索阶段：

1. **观察与生存**：观察试错、用火、石器、住所、饮水和经验传递。
2. **积累与协作**：农业、畜养、储藏、计数、测量、季节、灌溉与织造。
3. **火与材料**：陶器、木炭、铜与青铜、铁与钢、玻璃、灰浆和早期动力。
4. **记录与求证**：文字、几何、印刷、对照实验、代数、航行、卫生、显微观察与概率。
5. **机器与尺度**：机床、标准件、蒸汽、能量核算、定量化学、矿业与反馈。
6. **电力与工业**：电池、发电、电机、电网、工业化学、钢铁、冷链与生命科学。
7. **微观与精密**：精密测量、真空、原子证据、半导体、晶体管、无线通信与控制。
8. **计算与网络**：集成电路、计算机、算法、网络、自动化、光伏、电池和工业制造。
9. **智能与新发现**：机器学习、训练计算、智能体、机器人与闭环研究。

这些是**本地图的能力组织层级**，不是统一的历史年代，不暗示每一种文明都必须按同一种顺序发展。不同环境、资源和协作方式可以产生替代路径；同一阶段内部也有发展顺序。

### 两种关系，不要混在一起

- `enables`：已有能力 → 新能力。决定地图的横向布局，必须是无环图，不能指回更早阶段。
- `explains`：理论 → 被解释的现象或工艺。默认隐藏，可独立开启；可以指向左边，因为解释常晚于工艺。

用火不必先学习热力学，陶器不必先知道电子轨道；经验上的成功可以先发生，现代模型则帮助解释、预测和改进。

使能关系另分为：

- `required`：本图这条具体路线的关键前置，不代表所有历史路线的普遍必要条件。
- `support`：有帮助的能力，不是硬门槛。点线表示。
- `alternative`：一条替代路径，不应该把所有候选都要求为同时成立。长虚线表示。

本项目不把这些标签变成自动解锁证明，也不声称列出了某项技术的全部充分条件。回收利用属于物料反馈，不应该制造“先有回收才有第一件产品”的前置循环。

## 一个节点，不只是一个名称

每个节点都包含五个具体步骤：

**观察 → 尝试 → 推断 → 验证 → 新能力**

另有：要解决的问题、机制、解释、例子、常见误区、适用范围、尚待解决的问题和来源。

- 实践节点列出典型的**输入 → 处理 → 输出**以及产线角色。
- 理论节点说明模型如何从证据形成、在什么条件下有用。
- 观察入口帮助发现问题，而不是直接赠送技术。

图标的形状表示节点性质：实践为方形，理论为空心圆，观察入口为双环。颜色只表示学科；不能把“物理”误当作“只能是理论”。

阶段按钮可以走近局部，“全树”或缩放工具的适配按钮回到整体。选中节点后可查看前置能力、向右发展的可能和后来形成的解释；局部探索按“前置—当前—后续—再后续”展开。搜索覆盖节点、机制、产线和阶段。

学习标记仅保存在当前浏览器的 `localStorage`，不自动勾选前置节点，不阻止浏览，也不是工程能力、安全资质或实验认证。

## 对“足够强的智慧体”的约束

智慧不能替代物质条件。走向自主发现仍需要：

- 原料、能源、水、食物、场地、工具和维护；
- 可校准的测量、重复实验、误差模型和负结果记录；
- 可靠的制造、协作、通信与知识保存；
- 在物理环境中可执行的行动，以及独立复核；
- 安全边界、法律和环境约束。

闭环研究节点的终点不是“会生成答案”，而是**提出假说—安排受约束的实验—采集结果—判断证据—修正模型—接受外部复核**。语言输出不等于技术发现，仿真不等于制造成功。

危险的高温、冶炼、压力、电力和工业化学节点只提供概念性路径或数据比较，不构成家庭操作说明；饮水处理和食品接触材料的学习例子也不等于实际安全判定。

## 数据与运行

无需 npm 依赖：

```sh
node build.js
python3 -m http.server 5173
```

打开 `http://localhost:5173/`。页面也可从静态文件使用：`knowledge.js` 是由 `kb.json` 生成的内嵌数据，页面不依赖在线接口或 CDN。公式使用仓库里的 KaTeX 和 mhchem，字体也位于本地。

- `kb.json`：唯一维护的知识数据源，包括阶段、节点、关系、路线和参考来源。
- `knowledge.js`：生成文件，不手工修改。
- `app.js`：阶段导航、布局、搜索、详情、计算器和本地学习记录。
- `index.html`、`style.css`：页面结构与视觉设计。
- `build.js`：校验后生成数据包；`--out dist` 同时输出静态发布目录。
- `validate.js`：无依赖的数据校验。
- `browser-check.cjs`：可选的真实浏览器烟雾检查，使用 Node 22+ 和本地 Chrome CDP，不参与页面运行。
- `research/*.json`：本次早期、现代和原有节点发现环节的编写快照，保留来源检查说明；不是第二份运行数据源，后续修改以 `kb.json` 为准。

原有电解质量、电子层、罐体压力与 Gibbs 自由能计算器保留。所有计算器是有明示假设的教学模型，不是工业工艺计算软件。

## 继续扩展一个节点

1. 找到可观察、可对照的现象，不仅列出技术术语。
2. 指定具体资源与能力前置，区分关键、助力、替代。
3. 写出五步发现过程，验证标准必须能区分失败与成功。
4. 分开早期工艺经验和后来的理论解释。
5. 给出可追溯来源、公式范围、误区和未知边界。
6. 将新增能力放到右边，不人为制造前置循环。
7. 至少接入一条来自起点的可探索关系；路线中的相邻节点必须实际相连。
8. 运行：

```sh
node build.js
node validate.js
# 已有 localhost:5173 预览且 Chrome 开启本地 CDP 时，可选：
node browser-check.cjs
```

数据校验检查 ID、引用、完整发现环节、实践输入输出、阶段顺序、使能图无环、起点可达性、路线连续性和生成包一致性。浏览器检查逐节点详情、公式、横向箭头、阶段、路线、搜索、本地学习记录、旧计算器和移动端溢出。

## 仍未完成的部分

这是覆盖起源至自主研究的**核心主干**，不是人类技术的完整清单，更不是一个智慧体可以直接据此重建文明的操作手册。

还需要逐步深入矿物纯化、设备图纸与工艺窗口、工程可靠性、药品与临床、交通与航天、全套基础设施、组织制度、成本与生态约束。来源为机构说明、历史材料、教材及综述，不都对应某个假设世界里的首创实验；遇到需要检验的知识要继续接实证。

扩展的方向是增加可验证的能力链，而不是把整个文明压成一条必然的进度条。
